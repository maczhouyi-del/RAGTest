# P0 可执行任务板（仅技术门禁）

**来源：** v1.1 §§2–4、7–10（尤其 10.4）。  
**状态：** P0-00审查交付后用户已授权继续开发；P0-01—08本地部分实现/测试，P0-09/10补测准备与审查；完整P0门禁BLOCKED。下方保留任务验收要求，实际结果见本轮报告。  
**工作边界：** 此任务板将 P0 工程化，不批准实施 P1–P5，也不能宣称完成任何实测。

## 依赖与并行原则

```text
P0-00 基线/资源/契约审查
  ├─ P0-01 Tauri + Rust + Python Sidecar ────────┐
  └─ P0-02 SQLite/文件/Job 基础 ──┐              │
                                 ├ P0-03 解析 ─ P0-04 SourceAnchor/Chunk
                                 │                  └ P0-05 Embedding/增量
                                 │                           └ P0-06 向量同台评测
                                 └ P0-08 恢复/备份/安全（贯穿）
    P0-01 + P0-04 + P0-05 + P0-06 ─────────────── P0-07 GUI 来源跳转
    所有功能/安全检查 + P0-09 真实 Windows/性能 ─ P0-10 门禁总结
```

P0-08 不是最后再做；从 P0-02 开始实现时同步加故障测试。P0-09 可提前搭建 CI，但 CI 不等于最终实机验收。

## P0-00：项目基线与准入准备

- **目的：** 保证在投入大量代码之前，明确核心依赖、可执行验收条件、真实资源与安全边界。
- **输入：** v1.1 原文、历史 PR #4 风险记录、测试设备信息、合法 PDF 样本、用户授权边界。
- **可改动：** 项目脚手架、依赖清单、`docs/`、`contracts/`、预留 `tests/` 结构；先不建立大规模业务逻辑。
- **必须产出：** 当前环境/版本/模型许可表、至少一组可公开复现实验的真实许可 PDF 样本清单；API/实体草案差异表；P0 任务批准记录；装机/测量计划；空白报告模板。
- **验收：** 明确所有未知条件与阻塞；所有接口/任务路径有负责人和审查点；不把历史旧架构证据用于新架构 PASS。
- **依赖：** 无。

## P0-01：Tauri + React + Rust + Python Sidecar 最小进程闭环

- **目的：** 干净 Windows 11 上单 EXE 安装后无需系统 Python/Node/Docker/WSL 启动并退出。
- **功能：** Tauri 2 壳；最小 React 健康页；Rust 执行/回收 Sidecar；单实例；进程停止/异常提示；限定 IPC；启动随机会话凭据或命名管道 ACL。
- **必须证明：** Windows 无开发工具、非管理员、中文用户名、中文/空格安装与数据路径、Sidecar 意外退出与重新启动；无未认证监听端口；清理子进程。
- **反面测试：** 未授权 IPC 请求、重复启动、关闭时在途任务、恶意/错误路径；不能执行任意 shell。
- **验收证据：** 安装产物哈希、真实系统版本/环境、日志和进程检查记录、授权调用成功/拒绝用例。
- **依赖：** P0-00。参见 v1.1 §2.3–2.4、§8.1。

## P0-02：SQLite 数据、原件存储与最小持久 Job

- **目的：** SQLite WAL 作为真值，原始 PDF 存储不可变、导入幂等、任务重启后可恢复。
- **功能：** 可版本化 schema migration；Document/DocumentVersion/FileAsset 及基本 Chunk/Job 表；文件 SHA256 验证/去重；`queued/running/completed/failed/retry_wait/cancelled` 等任务状态；短事务/lease；错误码。
- **测试：** 重复同一 PDF 幂等、名称碰撞、部分写/磁盘满、锁冲突、正常及非正常关闭、schema 迁移失败可恢复；WAL 文件不得直接删除。
- **产出：** 迁移及 rollback/recovery 文档、数据库一致性断言/测试、可重入 Job 测试。
- **依赖：** P0-00。参见 v1.1 §3、§7。

## P0-03：真实 PDF 页级提取与质量升级路由

- **目的：** 用普通/双栏/表格/扫描/混合/旋转 PDF 确定提取质量，而非假设解析器准确。
- **功能：** PDFium 页文本/基础坐标；质量诊断信号；按页保留 ParseRun 版本与错误；当金标数据证明有必要时条件触发 Docling/OCR，记录路由原因。
- **必须证明：** 段落顺序、科学符号、页码、表格单元格与单位，低质量标识正确；错误/扫描页不得误标全文成功。
- **测试：** 许可证许可的 30–50 篇代表性样本是**逐级评测目标**，先最小合法子集冒烟，再逐步扩增；处理页数/扫描比例/耗时/峰值内存单独记录。
- **产出：** ParseRun schema 与逐页质量报告、路由/阈值候选及其测试原始记录。
- **依赖：** P0-02。参见 v1.1 §4.1–4.2、§9.2。

## P0-04：Chunk、Element 和来源坐标不丢失

- **目的：** 保留清洗文本与原 PDF 的对照，给最小阅读器提供可靠 SourceAnchor。
- **功能：** 基于结构边界 Chunk（文本/表格必须区分）；Element/SourceRegion/clean_offset 映射；保留来源版本、页面、低置信状态和 parse 指纹。
- **必须证明：** 同一测试文本片段能返回**正确 PDF 文件版本/页/区域**；旋转/CropBox/多栏/表格的坐标变换用真实样本验证，未校准返回 page-only。
- **反面测试：** OCR 修正或文本清洗发生长度变化；不得伪造 bbox 或错误文献版本。
- **依赖：** P0-03。参见 v1.1 §4.2、§6.2。

## P0-05：Embedding 持久化与严格增量

- **目的：** Embedding 与索引结构独立持久，新增/重复论文不会导致旧库全部重算。
- **功能：** EmbeddingSpace 完整指纹（权重哈希、tokenizer/预处理、维度/距离/归一化）；EmbeddingRecord/Chunk 关联；幂等新增/删除；批处理进度与缓存；本地轻量模型候选可配置。
- **测试：** 重复导入、新增 10 篇、重启后同一 Chunk 是否重算；变更模型参数必须建立新空间；损坏索引能由已保存向量恢复。
- **禁止：** 凭模型名字假设不同权重同空间；未测许可的模型自动下发；安装包强制附带大型生成 LLM。
- **依赖：** P0-04。参见 v1.1 §3.1–3.2、§4.4。

## P0-06：向量后端 A/B 同台 Benchmark 与适配器

- **目的：** 证据驱动选择 sqlite-vec 或 LanceDB，不将 ANN 作为既定方案。
- **功能：** `upsert/delete/search_exact/check_integrity/rebuild` 接口；A/B 真实 Windows 打包；一致过滤和可见性；IndexGeneration 只用于全量切换。
- **对比：** 同一 Embedding 向量和查询、距离、过滤、硬件及热/冷状态；KNN 结果正确性、P50/P95、磁盘/内存、增删性能、备份/恢复、中文路径、锁冲突。
- **禁止：** 不经对账把 SQLite 与 LanceDB 称为原子事务；选择了某方案后删除竞争者的失败/对照结果。
- **产出：** 可复现实验脚本/报告、ADR 决策书（编号以实际创建为准）；**没有数据保持 DRAFT**。
- **依赖：** P0-05。参见 v1.1 §3.3、§3.6、§9.5。

## P0-07：最小 GUI、检索来源与 PDF 原文定位

- **目的：** 用户导入/检索后可点击回到原文，不把 UI 模拟当真实索引。
- **功能：** 项目/文献最小视图、导入状态、检索面板、PDF.js 或等价合法阅读器、引用返回 PDF 文件版本/页/区域及置信等级。
- **必须证明：** 搜索结果后端真实存在；源 ID 在已授权范围内；非精确位置明确标注页级/区域级；长文本高亮与 PDF 缩放基本可用。
- **P0 限制：** 不要求完成 P3 生成式问答或 P4 证据矩阵；不可标注“科研结论已验证”。
- **依赖：** P0-01、P0-04、P0-05、P0-06。参见 v1.1 §5。

## P0-08：故障恢复、备份、隐私与对抗测试

- **目的：** 保障 PDF 原件、SQLite 真值、已保存向量、任务及人工成果（P3 后）可恢复。
- **功能：** SQLite Online Backup API、Manifest、SHA 对账、可选择备份目录、Sidecar 崩溃重启后租约回收、删除时先隐藏后清理。
- **测试：** 磁盘满、任务中断、坏页、坏索引、备份时增量写入、还原、路径迁移、异常关闭；恶意 PDF/Prompt Injection、超大/畸形文件、未授权联网、API Key/日志泄漏。
- **特别注意：** LanceDB 模式需有与 SQLite 匹配的向量快照策略；不能把数据库 Online Backup 等同跨存储一致备份。
- **依赖：** 与 P0-02 起并行持续；完成 P0-06 后补齐完整 A/B 备份恢复。参见 v1.1 §§3.5、7、8。

## P0-09：真实机器、性能/质量和安装门禁

- **目的：** 在 8GB/16GB 的干净 Windows 11 设备上验证交付物，而非只依赖 CI。
- **数据：** 渐进 30–50 篇基础 PDF → 100–200 篇检索模型比较 → 实际目标约 1000 篇的干扰/恢复与性能样本；3000 篇属于建议扩容档，只有实际材料可用才测。
- **指标：** P50/P95、内存/磁盘、解析成功/失败/待处理、文件/向量数、源锚定正确性、检索范围隔离、恢复可靠性。
- **性能承诺：** v1.1 的“16GB CPU 混合检索 P95 争取 ≤ 1s”只作初始目标；P0 可测基础组件，P2 完成混合检索后再正式判定全链路子系统。
- **依赖：** P0-01—08。参见 v1.1 §9。

## P0-10：GO/NO-GO 审查和下一阶段建议

- **输入：** 全部任务报告、原始日志/结果、版本许可表、残余风险/未测样本及批准门槛。
- **输出：** `GO / CONDITIONAL GO / NO-GO / BLOCKED` 建议、需人工确认的问题、P1 可启动或禁止启动的清单。
- **准则：** 核心 P0 否决项出现 FAIL/NOT EXECUTED/BLOCKED 时**不得自行宣布 GO**；测试证据由审批人复核。
- **依赖：** P0-09；详细门禁见 `P0-acceptance.md`。

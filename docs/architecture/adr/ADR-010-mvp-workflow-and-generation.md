# ADR-010：三入口 MVP、局部检索上下文与显式生成 Provider

状态：按2026-10-25用户MVP重构指令实施；工程与科研验收分别记录。

用户明确将产品收敛为导入PDF→持久索引→BM25/向量RRF→有引文问答；要求当前main直接实施并同步指定RAGTest。正文中通用新分支条款与开头具体指令冲突，按具体指令实施，计划中显式登记；不将源码同步授权扩展到论文、模型、凭据或安装包发布。

保留React/Tauri/Python/SQLite和已有安全、原件、备份、迁移、任务租约等机制。旧App原样保存为LegacyWorkspace，Research/复杂审查未删除。优先sqlite-vec作MVP验证，LanceDB继续同台基准，不锁定最终后端。

修正词法TF/中文单字、400码点重叠Chunk、E5溢出拒绝和索引文件完整性清单；schema13/14只增量增加投影和公开模型连接配置。新E5预处理指纹与旧空间隔离，不能承诺首次升级零重算，旧内容保留。原件/页偏移为引文权威，页级定位不冒充高亮。

MVP问答明确使用per_paper_limit=8，在Top-8中不因旧每篇3片段上限排除某篇的更相关片段；旧客户端省略字段仍取3，记录在任务payload以支持重现。这是针对真实BERT试验所见上下文截断的工程修复，不代表召回质量已被人工金标证明，也不把Top-K变成全库覆盖。

GenerationProvider复用本地隔离模型，加显式API与可选Magpie；用户每请求确认发送问题/检索片段到所选配置revision，冻结SHA，变化拒绝，不自动fallback。API密钥仅当前引擎会话内存，配置保存SQLite，重启需重输。暂不扩大为任意厂商SDK、代理自动发现或订阅凭据采集。Magpie按官方健康/模型列表/OpenAI兼容接口，网关路由可能出云，不能由localhost推断本地推理。

真实公开PDF/E5/本地Qwen的来源链、协议夹具、冻结程序/原生Rust传输、浏览器桥及Windows安装分开验证。Qwen在本轮出现不完整回答和被自检判矛盾的草稿，科研质量门禁仍BLOCKED；不改拒答标准。无人工金标不进行1000篇验收。详见contracts/mvp-v0.3.md与本轮报告。

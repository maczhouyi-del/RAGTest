# ADR-003 Sidecar IPC 与文件授权

- 状态：PROPOSED；决议 OPEN；日期2026-10-24；批准人待用户确认。
- 关联：D04，P0-01/02/07/08；v1.1 §§2.3–2.4、8.3、8.6。

## 问题与候选

候选 A：Rust 中转的随机127.0.0.1端口、每启动会话凭据；B：Windows命名管道及用户ACL。现有 OpenAPI 仅草拟 A，不能视为已选型；固定8765示例不得进入实现。前端不能持有 Sidecar token 或任意 shell 权限。

## 证据和裁定方法

[Tauri Sidecar 官方文档](https://v2.tauri.app/develop/sidecar/) 支持随包外部二进制及架构命名规则，但不能替代本项目安装/鉴权实测。当前未实施任何通道。比较启动握手、协议版本、凭据受控传递、回环绑定/ACL、旧令牌拒绝、并发/长度/超时限制、崩溃与子进程回收、中文普通用户安装。

还需定义 FileGrant 的签发、Sidecar 注册/兑换、用途/读写边界、单次或限时、撤销、链接/重解析点、TOCTOU 防护；鉴权会话不代替单文件授权。对 `/jobs`、source-anchor 和 diagnostics 同样复核资源访问，不因内部 API 跳过身份与 scope。

## 提议与回退

建议 A 作为 P0-01 首轮最小实验；只实现健康/生命周期，token经受控启动管道，不经 argv/日志/JS。B 保留可替代语义。尚未获批，不直接编码。明确威胁模型：同用户权限恶意进程隔离能力须实测，不以随机端口声称安全。失败关闭通道和结果发布，保留日志，不能回退到无认证端口。改变传输保留请求语义、契约版本和兼容说明。

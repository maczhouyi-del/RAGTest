## 4. 迭代失败与修复

失败日志与测试目录全部保留：

1. 最初使用 `python` 的编辑命令退出127，本机只有 `python3`；没有发生文件修改，随后改用python3。
2. 首轮 `browser.log`：删除可见日期后，一个名为“新会话”的历史项与创建按钮同名，严格定位失败。修复产品可访问性名称，未放宽到 `.first()`。
3. `build.log`：tabs键盘数组访问被严格TS规则拒绝（可能undefined）。加入目标存在检查；`browser-final.log`误启动于该失败构建后，主动中断退出130，整轮不计入验收。后续均先确认构建退出0再启动浏览器。
4. `browser-verified.log`：范围details与PipelineDiagnostics使用相同回答ID作为兄弟key，造成切换后重复节点。改用独立前缀key，并新增“每轮仅一个范围和过程”断言。
5. `browser-candidate.log`：前53项及UI主要验证通过，恢复后设置组件按新工作区重挂载，测试在重挂载前切分类导致输入等待超时。改为等待新工作区默认分类出现后再操作，保留元数据和无凭据断言。
6. 视觉复核发现窄屏导航规则误继承字号、搜索框双边框，以及焦点触发侧栏/设置外层滚动。已修正样式并在最终流程检查外层scrollTop和全部代表宽度。

最终 `browser-delivery.log` 退出0；不使用中间失败或旧bundle结果代替最终证据。

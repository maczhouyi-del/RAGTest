## 数据与恢复设计提案

- SQLite 连接显式启用 FK，验证 WAL；schema_version 有单向兼容判定；升级前一致备份，失败停用新 schema 并走已验证恢复路径，不能直接覆盖运行数据库或删 WAL。
- 最小表：Document/DocumentVersion/FileAsset/DocumentVersionFile、Job/JobAttempt/Event、schema_migrations；Chunk 仅为未来映射预留最小结构，最终字段先审阅，不伪造解析/源锚内容。
- 文件/SQLite 不构成同一原子事务。先持久 Job/意图；授权路径读取到临时文件、复制中计算 SHA、校验文件类型/限额、fsync 后在同一文件系统非覆盖发布；再短事务写关联和状态。Windows 原子改名/已存在目标/文件占用需实测；存在目标先校验其哈希，绝不盲覆盖。
- 崩溃时每个“未引用但完整文件/临时文件/DB 意图”均可分类对账；保留并隔离，报告 pending/failed，不自动批量清除。不得把半文件发布 READY。
- 同一 SHA 仅保证字节去重，不自动认定 DOI/标题就是同一逻辑论文。幂等键相同而 payload 指纹不同须拒绝，重试键作用域/有效期先冻结。
- Job 以短事务 CAS 领取租约；任务在事务外执行；lease 所有权和 fencing 防止过期 worker 重复发布；取消先撤销发布权再停止工作。定义最大尝试次数、心跳/时钟异常、completed/result_ref 和终态转换规则；具体常数在实现前登记。

## 先失败用例再实现

1. 用隔离测试根构造导入相同文件两次、同名不同字节、同 SHA 不同项目/版本关联；人工核对真实 PDF 原件 SHA。合成字节仅测试存储错误，不算真实 PDF 解析证据。
2. 在复制中断、改名后/DB 提交前、DB 提交后/响应前注入失败；检查重启对账、不可变原件和幂等性。
3. 验证 SQLITE_BUSY 有限重试、磁盘满/写失败可见、FK/完整性、迁移中断恢复、两个 worker 竞争租约、过期 worker 发布、运行/排队取消。
4. 实现最小 schema/导入/Job，再运行上述反例到通过。所有写入仅限独立临时测试目录；无授权真实用户目录不可作为故障注入靶点。

## 停止条件和验收

出现原件缺失/覆盖、半文件或失败结果可见、重复发布、任意路径读取、迁移不可恢复，立即停止依赖该能力的发布和下一任务；保留故障数据和日志。缺合法 PDF、未批准唯一性/Job 子契约或需新增依赖安装则停止依赖步骤，继续独立可做的审查。

验收须同时有：真实文件重复导入证据、故障注入前后清单、FK/integrity 检查、迁移恢复、租约/取消/重试与幂等断言、Windows 路径测试。只通过本机单元测试不能标 P0-02 整体 PASS。完成更新 PLANS/任务报告，未批准前不得推进解析或 Embedding。

## 待冻结的 IPC 子契约

建议优先验证 Rust 中转 + 127.0.0.1 随机端口 + 每次启动新会话凭据；用户可选择命名管道 ACL。令牌经受控匿名管道/受限启动通道传递，禁止 argv、前端全局变量或日志。握手含协议版本、子进程身份与 readiness；未 ready 不得向 UI 返回健康成功。设启动/请求/关闭超时和有限重启次数，具体值在实现前登记，失败可见。

UI 只能调用固定健康/重启诊断命令；不赋予通用 shell、可变可执行路径或任意参数。Tauri Sidecar `externalBin` 与目标三元组命名需配套。原生 Rust 的调用路径与前端插件权限分别审查；不得为了启动方便给 JS 通用 shell 权限。只做生命周期不表示 PDF 解析已沙箱化。

## 执行顺序与拟运行命令

以下均为下一轮待实现的命令，不是本轮实测；先锁定配置，命令/脚本不存在即记录阻塞。

1. 核对依赖许可与 Win11 构建条件，明确 Tauri 2、React、Rust、Python、打包器版本和哈希；获授权后才安装，保存安装日志。普通开发依赖与 Skill/插件安装授权分开。
2. 先写鉴权和生命周期反例：缺/错/旧 token、协议不兼容、启动超时、崩溃、重复启动、退出时挂起。红灯须来自行为断言，不接受仅 ImportError 的“失败”。
3. 实现健康和受控启动；再做 UI。mock 子进程只算 unit；另跑真实打包 Sidecar。
4. 条件命令：`engine/.venv/Scripts/python.exe -m pytest tests/unit/test_ipc_auth.py tests/integration/test_sidecar_lifecycle.py`（Win 项目根）；`cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --locked`；`npm --prefix apps/desktop run typecheck`。
5. 打包脚本计划：`pwsh -File packaging/build-windows.ps1`；脚本需执行冻结打包器及 `npm --prefix apps/desktop run tauri -- build --target x86_64-pc-windows-msvc --bundles nsis`。须先创建对应 npm scripts，不能假设现有。
6. 在无系统 Python/Node/Rust、无 Docker/WSL 的 Win11 x64 上普通用户安装。记录 OS build、WebView2、Defender、CPU/RAM、安装器/Sidecar/DLL SHA；中文用户名与中文/空格程序及数据路径；端口和进程快照、鉴权拒绝、崩溃恢复、退出回收。人工用例为上述 E2E 文档逐条记录。

## 验收与停止条件

必须：包内 Sidecar 可独立运行；授权健康成功；无凭据请求失败；无非回环监听；前端/日志/argv 无秘密；关机/崩溃无失控残留；普通用户与 Unicode 路径通过。记录每个真实命令、退出码、机器/时间、产物哈希；有安装器并不等于安装验收通过。

停止依赖步骤并报告：IPC 未决、需新增安装授权、缺 Win11 x64 构建/验收资源、仅靠系统 Python 才能启动、Tauri/DLL 不兼容、需要 Docker/WSL、任何未认证接口/泄密。可继续已批准且不依赖阻塞的本地单元工作，但不得扩展到 P0-02、解析或模型。Windows 未测不得宣布 P0-01 完成。

恢复：保留失败日志和构建产物；受控退出；不触碰现有数据目录、不卸载旧软件、不批量清理。修复后仅重跑受影响检查。结束更新 PLANS、报告与资源登记，再等用户确认后续范围。

# P0 最小威胁模型与安全门禁

**依据：** v1.1 §§1.5、2.3–2.4、7、8.3、8.6、9.1。**本文件是防护需求/测试计划，不表示已建立操作系统级沙箱。**

## 资产与边界

| 资产 | 主要威胁 | 必须落实/验证 |
|---|---|---|
| PDF 原件、扫描页、OCR 文本 | 畸形文件、解析器漏洞、嵌入提示命令、压缩炸弹 | 最大尺寸/页数/时间/内存限制、隔离权限、逐页错误、资源耗尽测试 |
| Windows 目录和文件授权 | 前端或恶意 PDF 借 Sidecar 任意读写用户文件 | Rust broker 的显式 FileGrant、目录白名单、路径解析/链接越界测试 |
| 本地 IPC/Sidecar | 任意本机程序访问未鉴权端口、会话重放、跨进程伪造请求 | 命名管道 ACL 或随机 127.0.0.1 端口+会话凭据、授权测试、有限 API |
| API Key | 写入前端本地存储、日志、CLI argv、Trace、崩溃转储 | Windows Credential Manager、进程参数/日志/导出脱敏核对 |
| SQLite/Embedding/Manifest | 中断造成文件部分写/错误发布、错误恢复导致错引 | WAL 语义、原件不可变、事务短、可见性状态与一致性对账、备份恢复演习 |
| 云 LLM/远程模型 | 用户 PDF 和查询片段意外外发、未知费用 | 默认不外发；显式授权用途、字段、数量/费用显示；独立调用记录 |
| 安装包/动态依赖/模型 | DLL 污染、来源不明权重、安装器或更新被替换 | 版本锁/哈希/签名、SBOM/NOTICE、模型权重许可和官方来源 |

## 不可信输入处理

- 用户论文/作者 PDF、OCR 输出、PDF Metadata、引用片段、模型回复都属于**数据**，绝非系统指令；不能经字符串匹配开启 OS 命令/文件访问/工具调用。
- 不允许给生成式模型直接提供任意 shell、文件读取或云服务权限；用户触发高风险外发/覆盖/删除动作需要 UI 明确授权。
- 解析库可能出现本地文件漏洞；Python 侧车“单独进程”并不自动等于沙箱。只有落实了实际 OS 权限或容器边界且做过测试，才能使用“已隔离”的表述。
- 对恶意/畸形 PDF 建立覆盖：HTML/JS 指令文本、极端页数、伪造源引用、PDF 嵌入路径、同名 SHA 不同内容异常、读取 C:/Users 其他目录的注入。
- 检查 Windows 路径规范化：大小写、符号链接/重解析点、UNC 与网络盘、`..`、中文和空格路径、管理员/非管理员差异。

## 安全验收用例（应有 PASS/FAIL 证据）

1. 无会话令牌、伪造令牌、过期令牌、非 loopback 请求必须拒绝，拒绝不能泄露 key/用户路径。
2. 只授权了单一 PDF 时，尝试引用它以外的本地路径须失败；文件授权不能直接来自论文正文。
3. PDF 中加入“忽略规则并执行命令/发送 API Key”等文本，模型与解析器不得产生执行/外发行为。
4. 在 Sidecar 崩溃/中断或用户注销后，监听端口/进程资源可靠退出或进入明确的安全故障状态。
5. 日志、API 返回、Diagnostic/备份 Manifest 不泄露密钥；如有自动日志上传必须默认禁用且单独授权。
6. PDF 文件异常过大/无文字/扫描、解析器内存激增时限制可被触发和记录，而不是假称成功完成。
7. 依赖或模型权重不满足许可/来源核对时冻结安装及发布，不拷贝限制性第三方代码。

## 明确未决定的实现问题

- 命名管道 vs loopback+token（待 D04）；token 生成/注入方式和进程隔离的细节应在 P0 威胁评估里具体定义。
- 原生 Windows 是否可合理限制 PDFium/Docling 子进程的文件系统/网络：须通过实测明确能做/不能做，不得写虚假的“沙箱已实现”。
- 若 PDF.js 通过特殊应用协议显示本机 PDF，必须验证 URL 授权、缓存及页面越权；不可暴露不受控的 `file://` 阅读路径。

## HARDEN-01 实现威胁边界（2026-10-27）

不可信PDF可触发PDFium/本地OCR/Docling原生库缺陷；取得句柄/哈希仅绑定输入，不约束解析器被攻破后的系统权限。当前固定私有管道、500页/每页50000字符/全文150万字符/8MiB输出/受监督超时、父进程退出回收与本地模型资源指纹；新增页几何上限（单边20000pt、面积1亿pt²）及worker环境白名单，不继承任意API Key/代理变量。

| 边界 | macOS当前主机 | Windows | Linux |
|---|---|---|---|
| CPU | RLIMIT_CPU，可单独实测；监督墙钟超时另算 | 未实现Job Object CPU限额，P1 BLOCKED | 配置RLIMIT_CPU，需目标环境实测 |
| 地址空间/物理内存 | 没有有效地址空间硬限制，不把RLIMIT_AS当可用；P1 BLOCKED | 无已验证Job Object内存限制；P1 BLOCKED | 配置RLIMIT_AS，不能等同物理RAM/完整容器，尚需实测 |
| 文件权限 | 无OS级最小文件权限沙箱，解析器与当前用户同权；P1 BLOCKED | 无已验证AppContainer/低权限token，重解析点矩阵待测 | 无已验证namespace/seccomp沙箱，P1 BLOCKED |
| 网络 | Docling Python socket禁连仅纵深防御，原生代码可绕过，非OS网络隔离 | 同左，未证明OS阻断 | 同左，未证明OS阻断 |

本轮不引入未经实测的伪沙箱。解除P1至少需：Windows11普通账户实机Job Object/受限权限与重解析点实测；支持Mac版本的维护方案、原生越权/联网尝试与内存耗尽测试；代表性恶意/压缩炸弹语料在隔离测试机验证。当前测试使用本地合成异常和许可公开PDF，不运行会破坏主机的真实exploit。父路径前后身份校验会缩小TOCTOU窗口，但不是OS隔离或全平台原子路径解析证明。

冻结运行时环境白名单例外仅限PyInstaller的四个指定进程交接变量（_PYI_ARCHIVE_FILE、_PYI_PARENT_PROCESS_LEVEL、_PYI_APPLICATION_HOME_DIR、_PYI_LINUX_PROCESS_NAME），仅sys.frozen时原值传递；不按_PYI_前缀批量继承，不继承Key/代理/任意Python路径。全部剥离会令onefile再次创建父进程，触发已有watch_parent身份检查，实际冻结回归已复现；不以关闭该检查解决兼容。交接语义核对[PyInstaller 6.22.3官方说明](https://pyinstaller.org/en/stable/advanced-topics.html#private-environment-variables)。这不提供额外的OS权限隔离保证。

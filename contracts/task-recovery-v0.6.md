# 任务恢复与准备范围 v0.6

HTTP DTO及端点不变；SQLite schema仍21，不修改旧迁移。准备接口仍允许1–1000个不重复、当前可见且获范围授权的版本。

新mvp_prepare任务在同一短事务保存既有scope_snapshots与job：快照包含排序后的doc_version_id、document_id、file_sha256；payload仅保存scope_id和scope_sha256。读取重新核对快照摘要。旧payload.versions继续可读；相同幂等键与相同范围返回原任务，范围不同返回IDEMPOTENCY_CONFLICT。准备处理完成、部分失败和接收入队分别报告，1000版本接收不等于已验证千篇性能。

取消在同一事务清除job租约并将关联queued/running answer_run置cancelled/JOB_CANCELLED。领取前取消不调用模型；执行中的租约失效不能发布完成。外部已到达服务商的请求不保证撤销，但本任务不调用付费服务。

重启后retry_wait可显式取消，已有导入/解析/元数据重试保持；其他需重新提交/重新授权。恢复副本检查既有非终态意图，同时IPC入口必须持有重型槽：已取消但仍在退出的实际执行者仍阻止切换。不能只根据job状态判断进程资源已释放。

旧版本数据库结构兼容；已有旧任务可读。新准备范围快照不作为科研引用或回答证据。未增加队列服务、自动云切换或无界任务载荷。

# CHAT-02 反馈修复契约 v0.11

2026-11-01；在 v0.10 上增量扩展，IPC `/v0`、握手 0.1.0、SQLite schema20 不变。本次无数据库迁移，不回写旧问答结果。

- 模型目录：使用服务真实返回的全部合法 ID；显示名依次取 display_name、name、ID。显式 select 不按当前输入过滤，保留手动输入模型 ID。目录中的多个模型不等于多个连接配置；后端一个有效远程配置约束不变。
- 恢复：归档管理列表直接提供恢复按钮，复用已有 manage/restore API；归档对象是对话，文献原件、索引不参与操作。加载、错误和成功反馈明确。
- 复制：用户触发复制当前问题或实际可见回答正文；右栏引用、诊断不拼入剪贴板。系统信息、摘录模式状态、拒答和必要错误保留性质标识；不将状态冒充模型生成正文。复制失败明确反馈。
- 题名范围：仅在调用者已授权、可见、项目匹配的版本内识别完整题名，及标题冒号前的有界英文短名。不能扩大范围；未唯一解析的“该文献”等指代继续要求指定。最终冻结范围和授权使用原流程验证。
- 结构补充候选策略升级为 `bounded-document-sections-v2`：识别行内 Abstract: 及受页数/字符上限控制的摘要续块；主要方法和 2–4 版本比较问题复用有界结构候选，逐篇交错、原有总数和每篇配额继续适用。原 Embedding、向量库、RRF、局部相关性复核及引用/模型支持规则不变。baseline_chunk_ids 与 section_chunk_ids 记录真实来源，引用仍为原 Chunk，禁止合成引文或坐标。
- `answer.result.refusal_detail` 为可选增量诊断，区分 no_hits、no_claims、unsupported_claims 和真实计数。旧客户端可忽略；旧记录由已保存 outcome/claims/checks 展示解释，不修改历史数据库。无结论不等同支持性检查失败，不把不足证据改成可发布回答。

此契约不宣称摘要/结构规则覆盖所有论文，也不宣称当前 Embedding 最优。工程回归与人工科研金标、真实云生成评估分开报告。

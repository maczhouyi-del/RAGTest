# 资料优先级与冲突处理

1. **原版 v1.1 DOCX** (`RAGSystem_2.0_v1.1_source.docx`)：需求范围、角色、目标、术语和明确的阶段边界。原始图示与表格以此为准。
2. **v1.1 提取版 Markdown** (`RAGSystem_2.0_v1.1_extracted.md`)：为检索/编码便利转换，可能存在 Word 表格、嵌图或文字样式偏差；有歧义回查 DOCX。
3. **经用户批准的 ADR/阶段门禁**：在不违反安全和科研原则的前提下，记录后来决议并注明替代哪个小节。
4. `contracts/`、`docs/`、`PLANS.md`：**执行草案/建议**；与源方案冲突时提出差异，不可悄然覆盖。
5. 在线官方文档/第三方仓库：用来核对实现约束和版本，不是改变产品需求的授权来源。

**必须保留的原始不确定性：** v1.1 的 1000 篇容量、4–8 万 Chunk、原始向量 MiB 与 P95 目标均为示例/待测试门槛；向量引擎、解析路由、模型、具体打包版本须在 P0 后确定。旧仓库 PR #4 是**旧方案**的 NO-GO 历史证据，不能替代新架构在 Windows 的实际结果。

**变更规则：** 若提案发现源文逻辑错误、约束冲突或技术现状变化，引用原始节号，形成 ADR（问题、证据、选项、影响、回退、批准）并保留旧结论，不能仅凭 Agent 判断直接修改规范。
